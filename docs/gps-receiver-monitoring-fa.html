پایش گیرنده GPS با Prometheus و Grafana

این راهنما مستقل از راهنمای اجرای گیرنده است. فرض می‌کنیم گیرنده روی اوبونتوی VirtualBox اجرا شده و با فرم شبیه‌ساز ویندوز دریافت موفق داشته‌اید. اینجا دو کانتینر دیگر را روی همان اوبونتو اجرا می‌کنید و نتیجه را در مرورگر ویندوز می‌بینید.

گیرنده GPSداده را دریافت و ذخیره می‌کند؛ هم‌زمان شمارنده‌ها و اندازه‌گیری‌های خودش را در خروجی متریک ارائه می‌کند.کانتینر فعلی روی اوبونتو
Prometheusهر ۵ ثانیه متریک‌های گیرنده را می‌خواند و تاریخچه عددی آن‌ها را ذخیره می‌کند.کانتینر جدا روی همان اوبونتو
Grafanaاز Prometheus آمار می‌خواند و به شکل نمودار و داشبورد نشان می‌دهد.کانتینر جدا روی اوبونتو؛ نمایش در مرورگر ویندوز

مسیر ارسال آزمایشی: شبیه‌ساز ویندوز ← اتصال TCP به گیرنده ← ذخیره فایل روی اوبونتو.
مسیر پایش: Prometheus متریک‌های گیرنده را می‌خواند؛ Grafana داده Prometheus را نمایش می‌دهد.

اینجا آمار عملکرد سرویس را می‌بینید، نه نقشه و مسیر خودرو. فایل‌های خام دریافت‌شده همچنان روی دیسک اوبونتو می‌مانند و به داشبورد منتقل نمی‌شوند.

۲. فایل‌های آماده چه تنظیماتی دارند؟

این فایل‌ها در مخزن آماده شده‌اند؛ برای شروع نیازی به نوشتن تنظیمات از صفر نیست:

فایلنقش
deploy/compose.yamlتعریف کانتینر گیرنده فعلی
deploy/compose.monitoring.yamlافزودن دو کانتینر Prometheus و Grafana، پورت‌ها، رمز و فضای ذخیره پایدار
deploy/monitoring/prometheus.ymlمشخص‌کردن گیرنده به‌عنوان منبع جمع‌آوری آمار
deploy/monitoring/grafana/provisioning/اتصال خودکار Grafana به Prometheus و بارگذاری داشبورد
deploy/monitoring/grafana/dashboards/gps-receiver.jsonداشبورد آماده با ۱۴ نمودار و شاخص

بخش اصلی تنظیم Prometheus این است:

global:
  scrape_interval: 5s
  scrape_timeout: 3s

scrape_configs:
  - job_name: gps-receiver
    metrics_path: /metrics
    static_configs:
      - targets: [gps-receiver:9091]

یعنی هر ۵ ثانیه، خروجی /metrics را از پورت 9091 سرویس گیرنده داخل شبکه Docker بخوان. نام gps-receiver در همین شبکه به کانتینر گیرنده اشاره می‌کند.

Grafana هم به نشانی داخلی زیر وصل می‌شود؛ این مقدار از قبل در فایل منبع داده تنظیم شده است:

http://prometheus:9090

داخل کانتینر Grafana، نشانی localhost به خود Grafana اشاره می‌کند؛ این نشانی داخلی را با localhost ویندوز یا اوبونتو جایگزین نکنید.

۳. ارسال فایل‌های پایش از ویندوز به GitHub

اگر فایل‌های پایش هنوز ارسال نشده‌اند، در PowerShell اجرا کنید:

cd C:\Projects\FleetGPSTracking\FleetGPSTracking
git switch codex/gps-receiver
git status --short
git add .gitignore deploy/compose.monitoring.yaml deploy/monitoring docs/gps-receiver-monitoring-fa.html docs/gps-receiver-monitoring-fa.md
git diff --cached --stat
git commit -m "Add receiver monitoring deployment and Persian guide"
git push origin codex/gps-receiver

اگر این تغییرات را قبلاً commit و push کرده‌اید، ثبت دوباره لازم نیست. رمز را در Git قرار ندهید؛ فایل رمز فقط روی اوبونتو ساخته می‌شود.

۴. دریافت فایل‌ها روی اوبونتو

cd ~/projects/FleetGPSTracking
git status --short
git pull --ff-only origin codex/gps-receiver

اگر تغییر محلی ثبت‌نشده دارید، پیش از pull آن را بررسی و حفظ کنید. از اینجا به بعد، همه دستورهای اوبونتو را در همین پوشه پروژه اجرا کنید.

۵. انتخاب رمز Grafana — فقط بار اول، روی اوبونتو

پوشه خصوصی رمز را بسازید:

mkdir -p deploy/.secrets
chmod 0700 deploy/.secrets

بلوک زیر را کامل در Bash اجرا کنید. اگر فایل رمز قبلاً ساخته شده باشد، آن را تغییر نمی‌دهد. در بار اول، رمز قوی و غیرخالی وارد کنید؛ هنگام تایپ نمایش داده نمی‌شود:

if [ ! -f deploy/.secrets/grafana-admin-password ]; then
  read -r -s -p 'Choose Grafana admin password: ' GRAFANA_PASSWORD
  printf '\n'
  if [ -n "$GRAFANA_PASSWORD" ]; then
    printf '%s' "$GRAFANA_PASSWORD" > deploy/.secrets/grafana-admin-password
  else
    printf 'Password is empty. Repeat this step.\n'
  fi
  unset GRAFANA_PASSWORD
fi
test -s deploy/.secrets/grafana-admin-password && chmod 0644 deploy/.secrets/grafana-admin-password

اگر پیام خالی‌بودن رمز یا خطا دیدید، همین مرحله را دوباره انجام دهید و هنوز ادامه ندهید. فایل داخل کانتینر فقط‌خواندنی است؛ مجوز خواندن برای کاربر Grafana لازم است و پوشه والد خصوصی، دسترسی کاربران دیگر میزبان را محدود می‌کند.

رمز را نگه دارید؛ موقع ورود لازم است. پس از ایجاد اولیه دیتابیس Grafana، تغییر فایل رمز، رمز حساب موجود را تغییر نمی‌دهد؛ تغییرات بعدی رمز از داخل Grafana انجام می‌شود.

۶. بررسی تنظیمات و دریافت ایمیج‌ها — روی اوبونتو

اول درستی ترکیب دو فایل Compose را بررسی کنید:

sudo docker compose -f deploy/compose.yaml -f deploy/compose.monitoring.yaml config --quiet

اگر بدون خطا برگشت، ایمیج‌های آماده ابزارهای پایش را دریافت کنید:

sudo docker compose -f deploy/compose.yaml -f deploy/compose.monitoring.yaml pull prometheus grafana

Prometheus و Grafana از ایمیج رسمی اجرا می‌شوند؛ نیازی به ساخت Dockerfile جدید برای آن‌ها ندارید. نسخه‌های انتخاب‌شده در فایل Compose ثابت هستند: prom/prometheus:v3.13.5 و grafana/grafana:13.2.4.

تنظیمات Prometheus را با ابزار خودش بررسی کنید:

sudo docker compose -f deploy/compose.yaml -f deploy/compose.monitoring.yaml run --rm --no-deps --entrypoint promtool prometheus check config /etc/prometheus/prometheus.yml

باید پیام موفقیت دریافت کنید؛ در صورت خطا، قبل از مرحله بعد خروجی را بررسی کنید.

۷. اجرای پایش — روی اوبونتو

ایمیج گیرنده از مرحله قبل ساخته شده است. این دستور دو سرویس پایش را اضافه می‌کند و پورت تشخیصی گیرنده را هم روی localhost اوبونتو در دسترس می‌گذارد. ممکن است کانتینر گیرنده بازسازی شود؛ اتصال شبیه‌ساز را تا پایان این مرحله متوقف نگه دارید:

sudo docker compose -f deploy/compose.yaml -f deploy/compose.monitoring.yaml up -d --no-build

وضعیت هر سه سرویس و پیام‌های پایش را ببینید:

sudo docker compose -f deploy/compose.yaml -f deploy/compose.monitoring.yaml ps
sudo docker compose -f deploy/compose.yaml -f deploy/compose.monitoring.yaml logs --tail=50 prometheus grafana

هر سه سرویس باید بالا باشند. فایل دوم مکمل فایل اول است؛ آن را به‌تنهایی اجرا نکنید. پایتون یا SDK دات‌نت روی اوبونتو لازم نیست.

۸. مطمئن‌شدن از رسیدن متریک به Prometheus

روی اوبونتو، اگر curl نصب است:

curl --fail http://127.0.0.1:9091/healthz
curl --fail http://127.0.0.1:9091/metrics

اولی باید listening برگرداند؛ دومی فهرست عددی متریک‌ها را نمایش می‌دهد. قبل از ارسال شبیه‌ساز، شمارنده‌های دریافت می‌توانند صفر باشند.

پس از چند ثانیه، دسترسی Prometheus به گیرنده را بررسی کنید:

curl --fail --get http://127.0.0.1:9090/api/v1/query --data-urlencode 'query=up{job="gps-receiver"}'

در خروجی باید یک نتیجه با مقدار "1" ببینید. مقدار صفر یعنی Prometheus نتوانسته متریک را بخواند؛ نتیجه خالی در لحظه اول ممکن است به معنی انجام‌نشدن اولین جمع‌آوری باشد. این شاخص فقط موفقیت جمع‌آوری را نشان می‌دهد؛ دریافت دستگاه و ذخیره فایل را در تست مرحله بعد هم بررسی می‌کنیم.

۹. بازکردن داشبورد روی کامپیوتر ویندوز خودتان

در VirtualBox، شبکه NAT ماشین اوبونتو، بخش Port Forwarding، قانون زیر را اضافه کنید. قانون قبلی GPS برای پورت ۵۰۲۷ را نگه دارید:

گزینهمقدار
نامGrafana
پروتکلTCP
آدرس میزبان127.0.0.1
پورت میزبان3000
آدرس مهمانبرای DHCP خود VirtualBox خالی؛ برای آدرس ثابت، آدرس اوبونتو
پورت مهمان3000

در مرورگر ویندوز این نشانی را باز کنید:

http://127.0.0.1:3000

بازکردن Grafana در مرورگر

نام کاربری admin و رمز، همان رمزی است که روی اوبونتو انتخاب کردید. از بخش Dashboards وارد پوشه GPS Receiver شوید و داشبورد GPS Receiver — پایش سرویس را باز کنید. منبع داده GPS Prometheus و داشبورد به‌صورت خودکار از فایل‌های پروژه بارگذاری می‌شوند.

برای دیدن خروجی روی ویندوز، فقط انتقال پورت Grafana لازم است. پورت‌های ۹۰۹۰ و ۹۰۹۱ فقط روی localhost خود اوبونتو منتشر شده‌اند؛ برای آن‌ها قانون VirtualBox نسازید. Grafana روی رابط‌های اوبونتو منتشر است تا انتقال پورت NAT کار کند؛ این تنظیم برای محیط آزمایش فعلی است و نباید بدون تنظیم دسترسی و HTTPS روی اینترنت عمومی منتشر شود.

۱۰. تست با همان فرم شبیه‌ساز ویندوز

cd C:\Projects\FleetGPSTracking\FleetGPSTracking
py -3 tools/GpsSimulator/gui.py

در فرم، آدرس 127.0.0.1، پورت 5027، تعداد دستگاه ۱۰ و فاصله ارسال ۲ ثانیه را بگذارید. «شروع» را بزنید و داشبورد مرورگر را کنار فرم باز نگه دارید.

آزمایش شماانتظار در داشبورد
شروع ۱۰ دستگاه، فاصله ۲ ثانیهاتصال فعال نزدیک ۱۰؛ شمارنده رکورد ذخیره‌شده افزایشی؛ نرخ پس از حدود یک دقیقه نزدیک ۵ رکورد در ثانیه
تعداد دستگاه را به ۵ تغییر دهید و «اعمال تغییرات» بزنیداتصال فعال نزدیک ۵؛ نرخ به‌تدریج نزدیک ۲٫۵ رکورد در ثانیه
فاصله ارسال را کم کنید و اعمال کنیدنرخ ورودی و رکورد ذخیره‌شده افزایش می‌یابد
«توقف» را بزنیداتصال‌ها به صفر می‌رسند؛ نرخ با تأخیر کاهش می‌یابد؛ سن آخرین بسته افزایش می‌یابد

داشبورد هر ۵ ثانیه تازه می‌شود، ولی نرخ‌ها از پنجره یک‌دقیقه‌ای محاسبه می‌شوند؛ تغییر نرخ آنی کامل نیست. نمونه شبیه‌ساز GPS معتبر ندارد؛ افزایش شاخص GPS نامعتبر طبیعی است و به‌تنهایی خطای پروتکل نیست.

۱۱. معنی شاخص‌های مربوط به گیرنده

شاخصمعنی

آمادگی TCP۱ یعنی شنونده TCP شروع شده است؛ تضمین سلامت دیسک نیست.

رکورد ذخیره‌شده و نرخ آنفقط پس از نوشتن و flush موفق بسته بالا می‌رود؛ ارسال مجدد نیز دوباره شمرده می‌شود.
GPS نامعتبررکورد ذخیره شده، ولی بررسی اولیه کیفیت موقعیت را رد کرده است.

نرخ ACKپاسخ تأیید در stream نوشته شده؛ اثبات دریافت پاسخ توسط دستگاه نیست.
مدت فعالیت، حافظه و CPUمربوط به فرایند گیرنده است، نه کل میزبان یا خودرو.

شناسه دستگاه و مختصات در متریک‌ها نیستند. با راه‌اندازی دوباره گیرنده، شمارنده‌های خودش صفر می‌شوند؛ Prometheus تاریخچه خوانده‌شده را نگه می‌دارد. متریک‌ها جای فایل خام یا دفتر حسابرسی دائمی را نمی‌گیرند.

۱۲. اگر خروجی را ندیدید

  • صفحه Grafana باز نمی‌شود: وضعیت کانتینر، انتقال پورت VirtualBox و آزادبودن پورت ۳۰۰۰ ویندوز را بررسی کنید.
  • ورود انجام نمی‌شود: رمز انتخابی مرحله ۵ را وارد کنید؛ رمز پیش‌فرض این راهنما نیست.
  • داشبورد نیست: log Grafana و وجود فایل‌های provisioning را بررسی کنید؛ منبع داده و داشبورد از فایل‌های مخزن می‌آیند.
  • نمودار بدون داده است: ابتدا مرحله ۸ را بررسی کنید، بعد شبیه‌ساز را شروع کنید. برای نرخ‌ها حداقل دو نوبت جمع‌آوری لازم است؛ زمان پردازش و سن آخرین بسته قبل از اولین بسته ممکن است بدون داده باشند.
  • خطای خواندن رمز: فایل رمز باید غیرخالی باشد و مجوزهای مرحله ۵ تنظیم شده باشند.

برای بررسی پیام‌ها:

cd ~/projects/FleetGPSTracking
sudo docker compose -f deploy/compose.yaml -f deploy/compose.monitoring.yaml logs --tail=50 gps-receiver prometheus grafana

۱۳. توقف، شروع مجدد و نگهداری

توقف فقط ابزارهای پایش، بدون توقف گیرنده:

sudo docker compose -f deploy/compose.yaml -f deploy/compose.monitoring.yaml stop grafana prometheus

اجرای دوباره:

sudo docker compose -f deploy/compose.yaml -f deploy/compose.monitoring.yaml up -d --no-build

از این پس برای فرمان‌های مربوط به کل مجموعه، هر دو فایل Compose را بیاورید. تاریخچه Prometheus و تنظیمات Grafana در volumeهای پایدار Docker هستند؛ دستور down -v آن‌ها را حذف می‌کند و در این روند لازم نیست.

نگهداری بلوک‌های Prometheus هفت روز یا حدود یک گیگابایت تنظیم شده است؛ فایل‌های جانبی می‌توانند فضای اضافه بگیرند. فایل‌های خام گیرنده همچنان در مسیر قبلی‌اند و این سیاست آن‌ها را پاک نمی‌کند.

این سند برای اجرای دستی شما آماده شده است؛ روی اوبونتو چیزی خودکار نصب یا اجرا نشده است. قالب فایل‌ها و اتصال تنظیمات بررسی شده‌اند، ولی اجرای واقعی Docker و نمایش داشبورد باید با همین مراحل روی اوبونتوی شما تأیید شود.

مراجع: فرمت متریک Prometheus، بارگذاری تنظیمات Grafana از فایل و اجرای Grafana با Docker.
