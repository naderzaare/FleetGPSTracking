راه‌اندازی گیرنده GPS و تست با شبیه‌ساز

این راهنما فقط سه کار را انجام می‌دهد: ارسال سورس از ویندوز به گیت‌هاب، ساخت و اجرای گیرنده روی اوبونتو، و تست دریافت با فرم شبیه‌ساز ویندوز.

برای وضعیت فعلی شما: پروژه روی ویندوز و اوبونتو وجود دارد؛ Docker و Compose روی اوبونتو نصب هستند. پایتون فقط روی ویندوز لازم است. همه دستورهای اوبونتو را در پوشه پروژه اجرا کنید، نه پوشه ذخیره داده.

۱. ارسال تغییرات به گیت‌هاب — روی ویندوز

در PowerShell وارد پوشه اصلی شوید و شاخه و تغییرات را بررسی کنید:

cd C:\Projects\FleetGPSTracking\FleetGPSTracking
git switch codex/gps-receiver
git status --short
git diff

فایل‌های گیرنده، شبیه‌ساز و همین راهنما را برای ثبت انتخاب کنید:

git add .gitignore .dockerignore src/GpsReceiver tools/GpsSimulator deploy/compose.yaml docs/gps-receiver-fa.html docs/gps-receiver-fa.md docs/gps-receiver-update-fa.md
git add -u
git diff --cached --stat

فهرست تغییرات انتخاب‌شده را بررسی کنید که فایل دریافت‌شده یا رمز در آن نباشد. سپس ثبت و ارسال کنید:

git commit -m "Update GPS Receiver service and deployment guide"
git push origin codex/gps-receiver

فقط پس از موفقیت ارسال، مرحله بعد را انجام دهید. این مرحله سورس را ارسال می‌کند؛ ایمیج روی اوبونتو ساخته می‌شود.

۲. دریافت نسخه جدید — روی اوبونتو

ابتدا ارسال فرم شبیه‌ساز را متوقف کنید. در ترمینال اوبونتو:

cd ~/projects/FleetGPSTracking
git status --short

اگر تغییر ثبت‌نشده‌ای دارید، قبل از ادامه آن را بررسی و حفظ کنید. در پوشه بدون تغییر محلی:

git switch codex/gps-receiver
git pull --ff-only origin codex/gps-receiver

۳. آماده‌کردن پوشه داده — روی اوبونتو

فایل‌های دریافتی در این پوشه میزبان ذخیره می‌شوند و با تعویض کانتینر باقی می‌مانند:

sudo mkdir -p /srv/fleet-gps/captures
sudo chown 1654:1654 /srv/fleet-gps/captures
sudo chmod 0700 /srv/fleet-gps/captures

۴. ساخت ایمیج؛ سپس اجرای کانتینر — روی اوبونتو

ابتدا فقط ایمیج را بسازید:

sudo docker compose -f deploy/compose.yaml build gps-receiver

پس از موفقیت ساخت، کانتینر را از همان ایمیج بالا بیاورید:

sudo docker compose -f deploy/compose.yaml up -d --no-build gps-receiver

وضعیت و پیام‌های سرویس را ببینید:

sudo docker compose -f deploy/compose.yaml ps
sudo docker compose -f deploy/compose.yaml logs --tail=30 gps-receiver

کانتینر باید وضعیت Up داشته باشد و این پیام در لاگ دیده شود:

GPS Receiver listening TCP 5027

۵. انتقال پورت VirtualBox برای تست از ویندوز

چون اوبونتو در VirtualBox با شبکه NAT است، در تنظیمات شبکه ماشین مجازی، بخش Port Forwarding این قانون را داشته باشید. اگر قبلاً ساخته‌اید، قانون تکراری نسازید:

گزینهمقدار
نامGPS
پروتکلTCP
آدرس میزبان127.0.0.1
پورت میزبان5027
آدرس مهمانبرای DHCP خود VirtualBox خالی؛ برای آدرس ثابت، آدرس اوبونتو
پورت مهمان5027

۶. تست فقط با فرم شبیه‌ساز — روی ویندوز

در PowerShell:

cd C:\Projects\FleetGPSTracking\FleetGPSTracking
py -3 tools/GpsSimulator/gui.py

در فرم این مقدارها را بگذارید:

گزینهمقدار اولیه
آدرس سرور127.0.0.1
پورت5027
تعداد دستگاه۱
فاصله ارسال۵ ثانیه

«شروع» را بزنید. تعداد اتصال باید به ۱ برسد و شمارنده رکوردهای تأییدشده افزایش پیدا کند. تعداد دستگاه یا فاصله ارسال را می‌توانید عوض کنید و «اعمال تغییرات» را بزنید. برای پایان، «توقف» را بزنید.

برای این تست، تنظیم فهرست دستگاه‌های مجاز در حالت خالی پیش‌فرض بماند تا شناسه ساختگی شبیه‌ساز پذیرفته شود.

۷. تأیید دریافت و ذخیره — روی اوبونتو

cd ~/projects/FleetGPSTracking
sudo docker compose -f deploy/compose.yaml logs --tail=20 gps-receiver
sudo ls -lh /srv/fleet-gps/captures
sudo sh -c 'tail -n 3 /srv/fleet-gps/captures/*.txt'

در لاگ عبارت accepted و records=1 و در پوشه، فایل متنی .txt انتظار می‌رود. داده شبیه‌ساز عمداً موقعیت GPS معتبر ندارد؛ این موضوع به‌تنهایی خطای دریافت نیست.

تست موفق یعنی فرم ویندوز اتصال دارد، شمارنده تأیید بالا می‌رود، لاگ اوبونتو دریافت را نشان می‌دهد و فایل متنی روی اوبونتو ذخیره می‌شود.
